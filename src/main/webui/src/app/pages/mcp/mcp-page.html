MCP

Se connecter au serveur MCP

L'application expose un serveur MCP (Model Context Protocol) qui permet à un assistant IA — Claude, un IDE, un agent — de consulter et piloter le planning en langage naturel : lister les référentiels, lancer une résolution, expliquer un score.

Le point d'entrée est {{ origin }}/mcp (transport HTTP streamable). Chaque requête doit présenter la clé API partagée dans l'en-tête X-MCP-Api-Key — c'est la valeur de la variable serveur PLANNING_MCP_API_KEY ; tant qu'elle n'est pas configurée côté serveur, le MCP répond 401 à tout le monde.

Confidentialité des animateurs : le serveur MCP ne renvoie jamais leurs données personnelles — ni nom, ni prénom, ni date de naissance, ni e-mail. Seuls circulent l'identifiant et les attributs de planification (statut majeur/mineur, manager, compétences et leur niveau, souhaits, indisponibilités). Ces données personnelles ne sont donc pas modifiables par MCP non plus : un animateur ne s'y met à jour que sur ses compétences, ses souhaits, ses indisponibilités et son statut manager. Un assistant qui ne lit jamais un nom ne peut pas le divulguer.

Proxy d'accès Pangolin détecté

Les en-têtes standard attendus par Pangolin sont P-Access-Token-Id (l'identifiant du jeton) et P-Access-Token (le jeton lui-même) — la configuration ci-dessus les inclut déjà. Un client incapable d'ajouter des en-têtes peut passer le jeton en query string : ?p_token=<id>.<jeton>.

Utilisez bien l'en-tête dédié X-MCP-Api-Key pour la clé API plutôt que Authorization: Bearer : un proxy d'accès consomme fréquemment Authorization pour son propre compte, et la clé n'arriverait jamais à l'application.
