### The solve budget, the queue and the public instance

- **Before (3.x)**: each edition set its own maximum solve duration and stop without improvement (the *Solver* screen, then *Planning rules › Solve*), under the operator's `SOLVER_SECONDS_LIMIT_MAX` and `SOLVER_UNIMPROVED_SECONDS_LIMIT_MAX` caps. Planned solves waited in a queue written to the database and **replayed at startup**. The two guards `SOLVER_MAX_SOLVES_PER_HOUR` and `SOLVER_MAX_QUEUED_JOBS` applied to any instance where they were set, and the application refused to start without legal notices on any production instance.
- **After (4.0)**:
  - **The budget is an instance setting**: `SOLVER_SECONDS_LIMIT` (900 s by default) and `SOLVER_UNIMPROVED_SECONDS_LIMIT` (180 s; `0`: never), the same for every edition, which the screen shows without changing. `SOLVER_SECONDS_LIMIT_MAX` now only bounds what a launch requests (`?seconds=`, MCP). `SOLVER_UNIMPROVED_SECONDS_LIMIT_MAX` is retired: setting it has no effect, and startup says so in a warning. Migration `V145` removes both settings from each edition; the ones an edition had set are kept in the `solve_budget_avant_4_0` table, which the application no longer reads and 5.0 will drop. A YAML scenario can no longer set its duration: the `parametresSolveur` field of an old file is ignored, and the import says so.
  - **The queue is in memory.** A restart of the application **loses** the solves that were waiting for their turn (and the ones that were running, as before). At startup, the jobs a 3.x left queued or running are marked *interrupted* in the solve history, with the reason written on the job, and the log gives their number: nothing restarts by itself. A solve that went to a remote compute machine is still followed.
  - **The quota only applies to a public instance**, declared by the new `PUBLIC_INSTANCE=true` variable. Without it, `SOLVER_MAX_SOLVES_PER_HOUR` and `SOLVER_MAX_QUEUED_JOBS` are ignored, with a startup warning if you set them. On a public instance, the refusal to start without the five required legal notices stays in place; on any other it becomes a **warning**.
- **What you do**: if an edition had set a duration or plateau of its own, find them after the upgrade in the `solve_budget_avant_4_0` table, and set `SOLVER_SECONDS_LIMIT` and `SOLVER_UNIMPROVED_SECONDS_LIMIT` to what you want for the whole instance. **If your instance is open to strangers (a public demo, for instance), set `PUBLIC_INSTANCE=true`**: without it, it no longer refuses to start without legal notices and no longer applies its quota. So that this break does not go unnoticed, an instance that does not set `PUBLIC_INSTANCE` and has its quota set, or incomplete required notices, says so at startup: it is no longer treated as public, and the warning names the variable. Set `PUBLIC_INSTANCE=false` to confirm it is not public and silence it. Before a restart, check that no solve is waiting in the queue: it would be lost. Scripts that wrote `dureeResolutionSecondes` or `plateauSecondes` through `/api/parametres-solveur` see those fields ignored; those that read `cappedFromSecondsLimit` or `cappedFromPlateauSeconds` on a job no longer find them.
