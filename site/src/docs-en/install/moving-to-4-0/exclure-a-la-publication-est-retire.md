### "Exclude from the publication" is removed

- **Before (3.x)**: the review list of a publication had a box per person, and the "Who received which version" table a "Defer" button: an unticked person received nothing and stayed to be notified. The body of `POST /api/planning/publication` carried `exclusions`, and the MCP tool `publier_planning` an `exclusions` argument.
- **After (4.0)**: a publication notifies **everybody** concerned. The boxes, the "Defer" button, the `exclusions` field and the MCP argument are gone; a client still sending `exclusions` gets a `200`: the field is ignored, and the answer carries an `avertissements` field saying the exclusion no longer exists (read that way until 5.0). "Notify only a few people" (`cibles`: the two people of an accepted swap, a replacement) stays, and defers the others as before. Existing exclusions are **ignored**: the deferred person was already to be notified, the next publication writes to them. The home alert closes person by person, once a publication has really notified that person (successful send); a person with no address, whose send fails or whom the publication defers keeps it. Migration `V160` stores every person whose last publication line was a deferral in `exclusion_publication_avant_4_0`, which the application no longer reads and 5.0 will drop, and the home screen shows one alert per person, stored **by identifier only**, never by name (the screen looks the name up when displaying, from the fiche). 3.x did not tell an exclusion deferral from a "notify only a few people" one: the archive keeps them all.
- **What you do**: before running the first 4.0 publication, read the home alerts (or `SELECT animateur_id FROM exclusion_publication_avant_4_0`): those people will receive their planning. If you wanted to call them first, do it beforehand. A script that sent `exclusions` must use `cibles`. Add the archive to your processing register ([retention](conservation-des-donnees.md#larchive-des-exclusions-de-publication-3x)): `DROP TABLE exclusion_publication_avant_4_0;` removes it with no effect on the application.
